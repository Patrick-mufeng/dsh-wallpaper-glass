## 一、一句话结论

这不是"一个插件"，而是**一个主包 + 8 个子包的插件族**：9 个 npm 包、96 个 JS 文件、约 6.3 万行源码、3.8 MB JS + 约 25 MB 静态资源、**47 条 HTTP 路由**、**147 个设置键**、约 **99 个可视控件**（滑块/开关/色板）。

它把「壁纸 + 液态玻璃主题」做得非常到位——你要的那部分确实好用；但同时塞进了**桌宠联动、点击拖尾特效、3D 视差、自定义头像、在线歌词/媒体桥、场景实时渲染降级链、整套预设导入导出、字体集编辑器**等一大堆独立功能，任何一个单拎出来都够做一个插件。

**可精简空间很大，而且大部分不需要改代码——行级停用就能关掉，见第四节。**

## 五、可精简项清单（按"裁掉的收益 / 风险"排序）

### A. 零风险：整包停用（改一行 YAML，不删代码，随时可恢复）

## 六、三档精简方案

### 方案①「温和」— 只停 4 个整包行，0 行代码改动
- 停：pet-link、fx、parallax、about-notice
- 保留：壁纸 + 玻璃 + 字体 + 吉祥物/头像 + 媒体桥 + 全部核心
- 收益：**省 438 KB JS + 20.6 MB 素材 + 7 条路由**，扩展页签只剩「自定义会话头像」一张卡
- 代价：几乎为零，随时改回来
- **推荐给你**

### 方案②「推荐」— 在①基础上再裁三条重链路
- 加裁：Scene/Web 实时渲染链、转码抽帧、主题预设快照
- 保留：壁纸播放（视频/图片/自定义上传）、**完整液态玻璃与外观**、字体、吉祥物
- 收益：再省约 **1.5 MB JS + 15 条路由 + ffmpeg 子进程依赖**，`client.js` 有望从 29,000 行降到 ~15,000 行
- 代价：失去场景壁纸实时渲染（本机没 WE，无感）、抽帧转码、一键预设
- ⚠️ 更正：媒体桥**不能整包停**（`/inventory` `/media` 在里面），只能删包内注册行
- **这是"主题功能好用 + 功能不过剩"最平衡的一档**

### 方案③「激进」— 只留「壁纸 + 玻璃 + 字体」一个包
- 把 9 包合成 1 个自建包，砍掉：预设、字体集编辑器、吉祥物、头像、全部扩展、诊断、遮挡、适配器矩阵、目录浏览器、省电三档（媒体桥的壁纸字节族必须保留）
- 目标：`client.js` ≤ 10,000 行、设置键 ≤ 60、页签 3 个（壁纸 / 外观 / 播放）

## 七、技术约束（改之前必须知道）

1. **`settings-schema.js` 是单一真源**：客户端、宿主、预设快照、模块重置、页签重置五处都从它派生。删一个键要同时看 `KINDS` / `DEFAULTS` / `SETTINGS_NAMESPACES` / `RESET_MODULES` / `RESET_TABS` / `PRESET_ASSET_KEYS` / `PRESET_EXCLUDED_KEYS` 七张表，还有守卫测试对账。**这就是"删键比删功能风险高"的原因。**
2. **子包停用是设计内行为**：`cordis.patch.yml` 注释里明说「停用本行 = 恢复宿主原生外观，壁纸/字体/吉祥物不受影响」，还有 `test/verify-component-visibility.mjs` 双向对账保证"不渲染 ≠ 白屏"。这是最安全的裁剪路径。
3. **主包对自己的子包做启动自检**：`assertSubpackagesResolvable` 解析不到会**大声抛错**（故意设计）。所以别从 `dependencies` 里删子包却留着 patch 行。
4. **`package.json` 的 `files` 白名单很长**：如果走源码目录改，注意 `assets/readme/*` 那 863 KB 是纯 README 插图，可以整目录删掉不影响运行。
5. **两处 `assets` 重复**：主包根目录 `icon.png` 185 KB × 9 个包 = **1.6 MB 同一张图**。
6. **`about-notice` 会请求外网**（GitHub Star API，10 分钟 TTL + 落盘缓存）——纯隐私/离线角度也值得停。
